# plan-executor

自动按 `.plan.md` 中的 todos 顺序执行任务。

## 触发条件

满足以下任一条件时自动加载：

- 用户引用 plan 文件：`@xxx.plan.md`
- 用户说："执行计划"、"按 plan 执行"、"完成 todos"
- 用户说："Implement the plan as specified"（Cursor 自动翻译）

## 核心工作流

```
1. 读取 .plan.md 文件
   ↓
2. 提取所有 todos（含序号、标题、状态）
   ↓
3. 按顺序依次执行（可跳过的标记 skip）
   ↓
4. 每个 todo 完成后：
   ├─ 执行代码修改
   ├─ 更新 plan 文件状态 [✓] / [✗]
   └─ 用户确认（关键步骤）
   ↓
5. 所有 todos 完成 → 总结报告
```

## 工作流细节

### 1. 解析 Plan 文件

识别以下结构：

```markdown
# 计划标题

## 目标
[简要描述]

## Todos

### 1. 第一步标题
- 子步骤 1
- 子步骤 2

### 2. 第二步标题
- [ ] 待办项 A
- [ ] 待办项 B

### 3. 测试验证
- 验证项 1
- 验证项 2
```

支持的标记：

| 标记 | 含义 | 处理 |
|------|------|------|
| `- [ ]` | 待办 | 默认执行 |
| `- [x]` | 已完成 | 跳过 |
| `- [~]` | 部分完成 | 询问用户 |
| `- [!]` | 关键步骤 | 必须用户确认 |
| `### N.` | todo 编号 | 按编号顺序 |

### 2. 执行策略

**默认行为**：按 todo 编号顺序依次执行

**跳过机制**：

```
自动跳过：标记为 [x] 的已完成项
询问跳过：
  - 标记为 [~] 的部分完成项
  - 包含 "可选"、"如有时间" 的步骤
禁止跳过：标记为 [!] 的关键步骤
```

**用户确认节点**：

| 节点 | 确认内容 |
|------|----------|
| 第一个 todo 开始 | 理解计划 |
| 关键步骤 [!] | 重大变更 |
| 测试验证 todo | 测试结果 |
| 全部完成 | 最终验收 |

### 3. 进度更新

每完成一个 todo，更新 plan 文件：

```diff
- ### 2. 第二步标题
- - [ ] 子步骤
+ ### 2. 第二步标题 ✓
+ - [x] 子步骤
```

更新规则：

- 不修改 plan 文件结构
- 仅添加完成标记
- 不删除原有内容
- 保留 plan 文件作为历史记录

### 4. 异常处理

**场景 A：执行失败**

```
Todo 执行失败
    ↓
记录失败原因到 plan 末尾的 ## 失败记录 部分
    ↓
询问用户：
  - 重试此 todo
  - 跳过此 todo（标记 [~]）
  - 中止整个 plan
    ↓
继续后续 todos 或中止
```

**场景 B：用户中途打断**

```
用户发送新消息
    ↓
保存当前进度（更新 plan 文件状态）
    ↓
执行用户新指令
    ↓
用户可要求 "继续 plan"
```

**场景 C：plan 文件不存在**

```
询问用户提供 plan 内容
或
引导用户创建：
  - 读取项目 docs/bootstrap.md
  - 询问任务目标
  - 自动生成 plan 草案
```

## 注意事项

### 必须遵守

- 严格按 plan 顺序执行（除非用户明确要求调整）
- 关键步骤必须用户确认
- 不修改 plan 文件本身（仅添加完成标记）
- 执行失败必须记录
- 测试验证 todo 不可跳过

### 推荐实践

- 每个 todo 开始前简述要做什么
- 每个 todo 完成后说明做了什么
- 跨多个 todo 时提供进度报告
- 全部完成后提供完整总结

### 禁止行为

- 跳过关键步骤 [!]
- 跳过测试验证 todo
- 删除 plan 文件内容
- 不更新 plan 状态就进入下一个 todo
- 一次性完成所有 todo 而不汇报进度

## 输出模板

### 单个 todo 完成

```markdown
### Todo N 完成：<标题>

**改动**：
- 文件 X：<变更描述>
- 文件 Y：<变更描述>

**下一步**：Todo N+1 - <标题>
```

### 全部完成

```markdown
## Plan 执行完成

**总计**：N 个 todos
**耗时**：约 X 分钟
**关键改动**：
- <改动 1>
- <改动 2>

**测试结果**：<通过/失败>
**ISS 状态**：<新增/更新>

**建议后续**：
- <建议 1>
- <建议 2>
```

## 反模式

| 反模式 | 后果 | 正确做法 |
|--------|------|----------|
| 一次性完成所有 todos | 用户无法介入 | 分步汇报 |
| 跳过关键确认 | 重大变更错误 | 关键步骤必须确认 |
| 不更新 plan 状态 | 进度不可见 | 每步更新 |
| 修改 plan 内容 | 破坏历史记录 | 仅添加标记 |
| 失败不记录 | 问题无法追溯 | 记录到失败记录 |
