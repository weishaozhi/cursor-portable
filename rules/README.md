# d:\ai\projects 项目规则

本目录包含所有子项目遵循的通用规则。这些规则从项目文档中提炼，确保代码质量和团队协作效率。

## 规则列表

### 核心规则（必须遵守）

1. **[project-structure.md](./project-structure.md)** - 项目结构与文档规范
   - 标准文档结构（bootstrap/prd/arch/project_state/test/git-usage）
   - 架构调整流程
   - 已知问题管理（ISS 编号）
   - 测试通过率维护

2. **[git-workflow.md](./git-workflow.md)** - Git 工作流规范
   - 提交命名格式（type + 时间戳 + 描述）
   - 分支模型（main/pre/feature/bugfix）
   - 分支保护规则
   - 常见反模式

3. **[testing.md](./testing.md)** - 测试与质量保证规范
   - 测试目录结构
   - 退出码约定（0/1/2）
   - 测试通过率维护（禁止写死 PASS）
   - 测试失败应对流程

4. **[architecture.md](./architecture.md)** - 架构与模块设计规范
   - 技术栈一致性（FastAPI + Vue 3）
   - 模块划分原则
   - 配置管理（单一来源）
   - 可观测性要求

5. **[api-design.md](./api-design.md)** - API 设计与文档规范
   - RESTful 设计原则
   - 请求/响应格式
   - Pydantic 模型设计
   - 认证与 WebSocket

### 专项规则

6. **[toolbox-integration.md](./toolbox-integration.md)** - Toolbox Hub 工具接入规范
   - 单进程 vs 多进程工具
   - tools.json 配置约束
   - 启动器模板（强制子进程清理）
   - 接入后自检流程

### 元规则（自我改进）

7. **[knowledge-evolution.md](./knowledge-evolution.md)** - 知识沉淀与持续改进
   - 对话结束后自动询问知识沉淀
   - 主动识别可优化的规则

   - 规则变更记录维护
   - 阈值设定依据：米勒定律（7±2）、邓巴数字（5/15/50/150）、三次法则

## 快速参考

### 创建新项目时
1. 初始化 Git 仓库
2. 创建标准文档结构（`docs/project/`）
3. 定义技术栈（参考 architecture.md）
4. 设置测试框架

### 添加新功能时
1. 检查是否需要更新 `prd.md`
2. 如果涉及架构变更，先更新 `arch.md`
3. 遵循 Git 提交格式
4. 编写对应测试

### 修复 Bug 时
1. 在 `project_state.md` 中登记 ISS-XXX
2. 编写回归测试
3. 修复代码
4. 更新 ISS 状态为 🟩

### 接入新工具到 Toolbox Hub 时
1. 阅读 `toolbox-integration.md`
2. 确定单/多进程模式
3. 配置 tools.json 和 config.yaml
4. 多进程工具必须编写 launcher
5. 执行完整自检流程

### 对话结束时（自动触发）
1. AI 自动分析本次对话使用的方法
2. 判断是否值得沉淀为技能
3. 主动询问是否创建技能或更新文档
4. 检测规则优化机会并提出建议

## 强制约束（不可违反）

### 文档
- ✅ 架构变更**必须先更新** `arch.md`
- ✅ 已知问题**必须登记** ISS 编号
- ✅ 测试通过率**必须真实记录**

### Git
- ✅ 提交信息**必须遵循**格式：`<type><YYYY_MM_DD_HH_MM>_<name>`
- ✅ `main` 分支**禁止** `push --force`
- ✅ 单次提交**只包含**相关改动

### 测试
- ✅ 新功能**必须有**测试
- ✅ Bug 修复**必须有**回归测试
- ✅ 提交前**必须运行**相关测试

### 架构
- ✅ 端口号**仅在** config.yaml 定义
- ✅ 敏感信息**禁止**硬编码
- ✅ 多进程工具**必须**实现 `_force_kill_children`

### API
- ✅ API 变更**必须同时更新** `docs/API.md`
- ✅ 错误响应**必须返回** JSON
- ✅ 用户输入**必须使用** Pydantic 验证

### 知识沉淀（自动执行）
- ✅ 对话结束后**必须询问**是否沉淀为技能
- ✅ 发现规则问题累计 **2-3 次必须主动建议**优化
- ✅ 单分类技能数量 > **15** 或全局 > **50** 时**必须提醒**整理
- ✅ 技能重叠度 > **60%** 时**必须建议**融合
- ✅ 技能 **6 个月未使用**时**必须建议**归档

## 规则应用优先级

1. **安全规范** > 其他规范
2. **强制约束** > 推荐实践
3. **项目级规则** > 个人偏好
4. **专项规则**（如 toolbox-integration）在适用场景下优先级最高

## 如何使用这些规则

Cursor AI 会自动读取这些规则并在代码生成、review 时应用。你也可以：

1. **查看规则**：直接阅读 `.cursor/rules/` 目录下的 Markdown 文件
2. **引用规则**：在 PR 描述或代码 review 中引用规则编号
3. **更新规则**：规则不是一成不变的，发现不合理之处可以修改
4. **新增规则**：使用 `/create-rule` 技能创建新规则
