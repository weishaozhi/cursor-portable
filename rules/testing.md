# RULE: 测试与质量保证规范

## 触发条件
- 编写新测试
- 修改现有测试
- 运行测试套件
- 添加新功能或修复 bug

## 强制约束

### 1. 测试目录结构（标准）

```
tests/
├── test_<module>.py       # 按模块组织测试文件
├── test_<service>.py      # 服务层测试
├── test_<model>.py        # 模型测试
└── conftest.py            # pytest fixtures
```

命名规则：
- 测试文件：`test_*.py`
- 测试函数：`test_<功能描述>()`
- 测试类：`Test<ClassName>`

### 2. 测试层级

| 层级 | 适用场景 | 工具 | 验收标准 |
|------|---------|------|---------|
| 单元测试 | 算法、模型方法、工具函数 | pytest | 快速（< 1s）、隔离 |
| 集成测试 | 模块组合、API 端到端 | pytest | 覆盖关键路径 |
| 启动器测试 | 多进程工具（仅 toolbox_hub） | pytest | 路径解析、进程管理 |

### 3. 退出码约定（严格遵守）

| 退出码 | 含义 | 说明 |
|--------|------|------|
| 0 | 全部通过 | 所有断言成功 |
| 1 | 至少 1 个 `AssertionError` | 存在测试失败 |
| 2 | 脚本自身异常 | 非断言错误（导入失败、语法错误等） |

### 4. 测试通过率维护（test.md）

**必须**在每个项目的 `docs/project/test.md` 中维护通过率表格：

```markdown
| 脚本 | 上次运行日期 | 退出码 | 备注 |
|------|-------------|--------|------|
| `tests/test_solver.py` | 2026-08-30 | 0 | 8 项 |
| `tests/test_models.py` | 2026-08-30 | 0 | 13 项 |
```

**严禁**：
- ❌ 写死 "全部通过" 或 "100%"
- ❌ 不更新运行日期
- ❌ 隐瞒失败的测试

### 5. 编写测试的规范

每个测试文件顶部必须注明：
```python
"""
测试模块：<模块名称>

覆盖场景：
- 场景 1
- 场景 2

前置条件：
- 条件 1
- 条件 2
"""
```

### 6. 测试数据管理

- 使用 pytest fixtures 管理测试数据
- 避免硬编码路径（使用 `Path(__file__).parent`）
- 敏感数据不得出现在测试代码中
- 测试数据应最小化（最小可复现集）

## 工作流程

### 写一个新测试的流程

1. **确认主题**：检查 `tests/test_<module>.py` 是否已存在
2. **编写测试**：遵循 §5 编写规范，包含文档字符串
3. **本地运行**：
   ```bash
   pytest tests/test_<module>.py -v
   ```
4. **记录结果**：确认退出码符合 §3
5. **更新文档**：
   - 更新 `docs/project/test.md` §6 通过率表
   - 更新 `README.md` 的测试统计（如有）
6. **提交信息**：明确写出 "新增测试 …（退出码 X / N 项断言）"

### 测试失败应对流程

```
测试失败
    ↓
是预期行为变更？
    ├─ 是 → 更新测试断言 + 更新文档
    └─ 否 → 真实回归
            ↓
        1. 在 project_state.md 新建 ISS-XXX
        2. 最小复现 bug
        3. 修复代码
        4. 验证测试通过
        5. 更新 ISS 状态为 🟩
```

## 质量门禁

### 提交前必须

- [ ] 运行相关测试并通过
- [ ] 新增功能必须有对应测试
- [ ] Bug 修复必须有回归测试
- [ ] 更新 `test.md` 通过率表

### 合并到 main 前必须

- [ ] 全部测试套件通过（退出码 0）
- [ ] 测试覆盖率不下降
- [ ] `test.md` 已更新

## 禁止行为

- ❌ 提交前不运行测试
- ❌ 注释掉失败的测试
- ❌ 在测试中使用 `sleep()` 等待（除非测试异步/定时器）
- ❌ 测试依赖外部服务（未 mock）
- ❌ 测试之间有依赖关系（必须独立运行）
- ❌ 测试修改全局状态而不清理
