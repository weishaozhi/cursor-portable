# RULE: 项目结构与文档规范

## 触发条件
- 创建新项目
- 修改项目架构
- 添加/修改文档

## 强制约束

### 1. 标准文档结构（必须）
每个项目必须包含以下文档在 `docs/project/` 目录：

```
docs/
└── project/
    ├── bootstrap.md          # 启动规范与文档索引（入口）
    ├── prd.md               # 产品需求文档
    ├── arch.md              # 技术架构文档
    ├── project_state.md     # 项目状态与已知问题
    ├── test.md              # 测试规范
    └── git-usage.md         # Git 使用规范
```

### 2. 文档职责分离
- **prd.md**：产品需求、功能清单、用户流程、页面清单、验收标准
- **arch.md**：技术栈、模块划分、数据流、部署链路、目录结构
- **project_state.md**：当前阶段、已知问题（ISS-NNN 编号）、下一步行动、项目统计
- **test.md**：测试层级、目录结构、通过率表格（禁止写死 PASS）
- **git-usage.md**：分支模型、提交命名格式、常见反模式
- **bootstrap.md**：文档索引、核心规范速查、修改边界说明

### 3. 架构调整流程
任何架构级调整必须：
1. **先修改** `arch.md`
2. **再修改** `project_state.md` 登记变更
3. **最后执行**代码修改

### 4. 已知问题管理
在 `project_state.md` 中使用 ISS 编号跟踪：

```markdown
| 编号 | 问题 | 优先级 | 状态 |
|------|------|--------|------|
| ISS-001 | 问题描述 | P1/P2/P3 | 🟨/🟩/❌ |
```

状态图标：
- 🟨 待处理
- 🟩 已完成
- ❌ 已关闭/不修复

### 5. 测试通过率维护
`test.md` 中的通过率表格必须：
- 记录**真实的上次运行日期和退出码**
- **严禁写死 PASS**
- 每次运行测试后更新表格

## 推荐实践

### 项目启动前必做
- [ ] 初始化 Git 仓库
- [ ] 创建完整的 `docs/project/` 文档集
- [ ] 在 `prd.md` 中明确核心/非核心功能边界

### 报错应对原则
1. **最小复现**：用最小数据集复现问题
2. **加观测**：补充日志、断点
3. **写小测试**：用单元测试锁住能稳定复现 bug 的行为
4. **登记 ISS**：在 `project_state.md` 中新建条目

## 禁止行为
- ❌ 架构调整不更新 `arch.md`
- ❌ 把同一个报错反复提交（没有新增证据）
- ❌ 测试通过率表格写死 "全部通过"
- ❌ 已知问题不登记 ISS 编号
